# IncidentOS 三分钟演示脚本

## 0:00–0:25｜无需文档开始

打开产品首屏。指出首屏已经说明用途，并直接提供两个真实感事故。选择“支付服务延迟突增”。

## 0:25–0:55｜多 Agent 调查

展示左侧七个调查角色与完成度。进入“事件流”，说明进度来自 `evidence-found` 等领域事件，不是定时器动画。

## 0:55–1:25｜证据化结论

返回“证据”，依次点击重试比率、链路间隔和发布灰度证据。指出每条都有时间、来源和稳定位置。主假设置信度为 96%，但还不能直接处置。

## 1:25–1:50｜反证而非集体赞同

打开“假设与反证”。展示 Skeptic 对“处理器独立重复结算”的判别测试：所有重复账本记录都能关联到重复网关请求，因此替代解释被排除。

## 1:50–2:20｜人工审批

先点击“拒绝”，展示没有产生 `action-executed`，系统仍停在审批状态。随后重新“批准并执行”，展示处置配置、影响范围和回滚方案。

## 2:20–2:40｜恢复验证

点击“运行恢复验证”。展示重试比率、支付成功率和重复扣款均满足预先声明的阈值；系统才变为“服务已恢复”。

## 2:40–3:00｜交付证据

点击“导出复盘报告”。快速展示 `plugins/incidentos/` 的 bundle patch、运行时 Skill 和系统提示词；指出同一个可安装插件同时改变 Agent 能力组合，这是 dsh 的差异化实现。最后展示 `npm run verify` 通过。
